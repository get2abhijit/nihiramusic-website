## 2. DNS and GitHub check (done by owner, verified on paper)

- Apex: 4 × A → 185.199.108.153 / .109 / .110 / .111. www: CNAME → get2abhijit.github.io. No AAAA (allowed: GitHub lists AAAA as optional). No wildcard records (GitHub warns against them). Matches the current GitHub docs.
- E-mail: MX (3 × mailhostbox), SPF, DKIM (20240229._domainkey), DMARC and the imap/pop/smtp/webmail CNAMEs are identical in the old Hostinger zone and the new BigRock zone. → e-mail unaffected. Test: send a mail to and from both mailboxes.
- CNAME file: added (`nihiramusic.in`). **GitHub ignores it** for sites deployed by a GitHub Actions workflow (like this one); the domain lives in Settings → Pages → Custom domain. Kept as a record and in case the site is ever deployed from a branch.
- "DNS check unsuccessful / NotServedByPagesError": most likely DNS caching. Resolvers that cached the old nameservers keep asking Hostinger's dns-parking.com (old zone still active, points to Hostinger) until the cached nameserver record expires (NS TTL there: 86 400 s = 1 day; allow up to 48 h). GitHub's check may hit such a resolver.

### Fix steps (from 2026-11-02, i.e. 48 h after the nameserver switch)
1. Settings → Pages: if the check is now green, tick **Enforce HTTPS** (GitHub: can take up to 24 h to become available).
2. Still red or "Certificate not yet created": at a quiet time click **Remove** next to the custom domain, type `nihiramusic.in` again, **Save**. This restarts the check and the Let's Encrypt certificate request (GitHub docs). The site is unreachable at nihiramusic.in for those seconds; the domain is verified, so nobody else can claim it.
3. Still failing after another day: check that no CAA record exists at BigRock (or that it allows `letsencrypt.org`), and that no extra A/AAAA/ALIAS record exists for `@`. Then ask GitHub Support (mention NotServedByPagesError and the nameserver change date).
4. Check (any computer):
   - Windows PowerShell: `Resolve-DnsName nihiramusic.in -Type A` and `Resolve-DnsName www.nihiramusic.in`
   - Mac/Linux: `dig nihiramusic.in +noall +answer -t A` and `dig www.nihiramusic.in +nostats +nocomments +nocmd`
   - `curl -I http://nihiramusic.in/covers` → `301` to `/covers/`; after step 1: `curl -I http://nihiramusic.in/` → `301` to `https://`; `curl -I https://www.nihiramusic.in/` → `301` to `https://nihiramusic.in/`.

## 4. Loading speed (issue reported on the live site)

Causes found in the code and setup, biggest first:
1. **No HTTPS yet.** Browsers use the fast HTTP/2 protocol only over HTTPS. Over plain http every page loads its ~10
   small files (CSS, scripts, data, fonts) over HTTP/1.1 with fewer parallel connections. Fixed by 3.1.
2. **Hero photo from Hostinger.** Home's largest image (1920 px) comes from assets.zyrosite.com, a second server,
   at full width even on phones. Fixed by 3.2 (local copies with 640/960/1280 px versions; the preload then uses them).
3. **DNS caches** still pointing at Hostinger for some visitors until about 2026-11-02 (section 2).
Re-measure with 3.8 after 1 and 2. Remaining tuning is an M6 candidate ("performance round 2").

## 5. Rollback plan

- **Website broken after a change** (not DNS): Actions → Deploy site → open the last green run → **Re-run all jobs**
  publishes that older version, or revert the commit on GitHub. DNS untouched.
- **Back to the old Hostinger site** (only if really needed): BigRock → nihiramusic.in → Name Servers → set
  `ns1.dns-parking.com` and `ns2.dns-parking.com`. The old Hostinger zone (incl. e-mail records) is still there and
  unchanged, so e-mail keeps working. Takes up to 24–48 h. In Hostinger hPanel check that the website is still connected
  to nihiramusic.in. Note: with a custom domain set, https://get2abhijit.github.io/nihiramusic-website/ only forwards
  to nihiramusic.in. To look at the new site during a rollback, click **Remove** under Settings → Pages → Custom domain;
  the github.io address then works again (the domain stays verified, so nobody else can claim it).
- **Forward again**: set the nameservers back to dns1–dns4.bigrock.in (BigRock zone unchanged).
- The rollback path exists only while the Hostinger plan runs (until 2028-09-27).
